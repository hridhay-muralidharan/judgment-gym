# Four-Hour Hackathon Runbook

This runbook is intentionally not executed before the hackathon.

## 0:00–0:20 — Repository and deployment

Create the public repository, add the application shell, configure Vercel and the server-side model route, add the deployment secret, and verify the first deployment. See [Vercel deployment notes](VERCEL_TEST_NOTES.md) for the tested workflow.

## 0:20–1:05 — Frontend reflection flow

Build landing, scenario, source drawer, response editor, optional prompts, draft persistence, and submit/loading states.

## 1:05–1:55 — Agent integration

Implement the constitution, typed modes, state transitions, structured reflection extraction, tentative interpretation, correction flow, and model-error recovery.

## 1:55–2:35 — Profile evolution

Build threads, tensions, evidence links, status changes, and revision history.

## 2:35–3:05 — Adaptive scenario

Implement strategy selection, selection explanation, follow-up generation, skip/regenerate, and user-authored scenario paths.

## 3:05–3:35 — Privacy and history

Build history, encrypted export/import, reset/delete, local recovery, and storage status.

## 3:35–4:00 — Verification and publication

Run tests and build, complete the five-scenario journey in a clean browser, test mobile layout and failure states, inspect for secrets/private data, push the final commit, verify the live deployment, and publish the repository and demo links.

## Acceptance criteria

- first-time user understands the product in under one minute;
- user can begin without an account;
- tentative interpretations are visibly distinct from user text;
- free-form corrections alter the profile;
- original evidence remains available;
- one pattern becomes context-dependent;
- one tension remains unresolved;
- next scenario is relevant and its reason is visible;
- export/import and delete/reset work;
- API key is server-side only;
- model failure is recoverable;
- complete journey works on mobile and desktop;
- README explains product boundary, agent model, privacy, and limitations.
