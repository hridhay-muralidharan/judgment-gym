# Build and share runbook

## Product path

1. Start with a lived situation.
2. Add optional felt, thought, speech, action, want, consequence, and present-meaning detail.
3. Review tentative model threads and correct them.
4. Inspect the selected probe and its rationale.
5. Respond to the clearly labelled constructed situation.
6. Compare the constructed response with the lived account.
7. Save or discard the exploration, then review the evolving model.

## Verification

- first-time user understands the lived-to-constructed loop;
- constructed situations are visibly distinct from lived accounts;
- model claims show uncertainty and evidence;
- user correction remains available;
- exploration can be skipped or stopped;
- transfer-back review is explicit;
- export/import and delete/reset work;
- API keys remain server-side;
- hosted-model failure falls back safely;
- mobile and desktop layouts remain usable;
- public documentation explains the privacy opportunity without claiming on-device capability today.
